# W5 Day5 学习笔记：项目模块化拆分
日期：2026/11/6

## 今日学习内容
- 为什么要拆分文件（好找，好改，好协作）
- 三层结构：data.py（数据）/models.py（逻辑）/main.py（入口）
- `__init__.py` 的作用：告诉 Python 这是一个包
- from data import cases 跨文件导入函数

## 拆分前 vs 拆分后
| 对比项 | 拆分前 | 拆分后 |
|---|---|---|
| 文件数量 | 1 个（case_cli,py） | 3 个（data.py/models.py/main.py） |
| 找数据问题 | 翻整个文件 | 去 data.py |
| 改筛选逻辑 | 改出问题整个程序崩溃 | 只改 models.py，不影响其他模块运行，风险较小 |
| 文件长度 | 80 行 | 每个文件 20-30 行 |

## 三个模块的职责
| 文件 | 职责 | 类比 | 
|---|---|---|
| data.py | 提供数据 | 采购员 |
| models.py | 处理数据 | 厨师 |
| main.py | 与用户交互 | 服务员 |

今天学习的知识帮我建立了项目模块化拆分的思维，可以提高代码的可维护性、可修改性和安全性，但是在真实的工程项目中，模块的数量、功能和代码的复杂程度远远不是当前的练习项目可比的，我的拆分思维目前还不足以应付这类真实的工程项目

## case_app 流程图
用户输入参数
    ↓
  mian.py 
接收并解析参数
    ↓
  models.py 
根据解析出来的参数进行逻辑筛选
    ↓
  data.py 
为筛选模块提供数据（筛选对象）
    ↓
  models.py 
根据提供的筛选对象以及解析的参数，筛选出结果
    ↓
  mian.py 
打印并显示结果
