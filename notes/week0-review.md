# W0环境周复盘
复盘日期：2026/10/04

## 这一周学了什么
这一周是 AI 应用工程师学习的第一周（W0环境周），主要学习了开发环境的搭建和基础开发工具的使用
- Day1：安装了 Python 和 VS Code，写了第一个 Python 程序 `hello.py`
- Day2：安装了 Git，注册了 GitHub 账号，并在 GitHub 中建立了远程仓库，将 Day1 写的 `hello.py` 程序上传到远程仓库中
- Day3：学会了虚拟环境的搭建和 pip 包的下载和管理
- Day4：学会了密钥保护，`.env` 文件放密钥和项目配置，`.gitignore` 文件放不上传 GitHub 远程仓库的文件
- Day5：学会了建立规范的文件夹结构，并写了这一周的学习笔记
- Day6：做了环境总检查，确认开发环境和开发工具都能正常运行
- Day7：对开发环境和开发工具做了二次复查，收尾复盘，并写了复盘报告，汇总提交W0环境周阶段成果

## 哪一步最难
我觉得Day3的虚拟环境搭建没有完全理解，如何从0开始搭建一个新的虚拟环境和该环境对应的依赖和工具包的安装，这些知识目前只有一点模糊的概念，后续我准备把这部分的知识拉出来重新看一遍，巩固一下这方面的知识，并在后续学习中，也需要注意一下这部分的内容

另外还有Day4的学习内容，这一天的学习中提到的 `.env` 和 `.gitignore` 这两个文件夹的作用和创建方式不是我觉得难的地方，这一天的学习内容中我觉得最难的地方是用 Python 程序调用工具去读取 `.env` 中的密钥内容，这部分的代码一开始完全没看懂，只是照着把 AI 给我的代码抄了一遍，每一行代码的作用完全不清楚，后来单独把这段代码给了 AI，让 AI 帮我解析了一下每段代码的作用，才大致搞懂这串代码的运行逻辑

最后最难的点就是 git 提交本地仓库的命令中的提交备注要用英语写，这对我一个英语白痴来说是一个极大的挑战，但同时也是一个提示我英语能力的好机会

## 卡在哪里，怎么解决的
第一个卡点就是第一次提交文件到 GitHub 远程仓库时系统一直用 Work Buddy 附带的 git 轻便版上传文件，虽然这个版本也能上传，但是对于我后续的学习有一定的影响，在解决这个问题的过程中，我与 AI 讨论，试了好多方法，先是修改 VS Code 中 git 的文件路径，又修改了环境配置的优先级，最后将这个问题的原因锁定在用户级凭证管理器配置（global credential.helper），这个配置的路径被 WorkBuddy 改成了便携版的路径，解决了这个问题后，上传路径终于改为 git 正式版了

第二个卡点就是用 pip 下载工具包时，遇到了请求超时的问题，pip 下载工具包时，默认从国外的官网下载，国内大概率会出现请求超时、下载速度慢以及连接失败等问题，为了解决这个问题，我将 pip 的默认下载地址改为了国内的清华镜像源，改完后请求下载成功，下载速度也很快，问题得以解决

## 这一周的收获
- 自己动手搭建好了一个基础的开发环境，以后学 Python、做项目都有了基础
- 学会将写好的代码上传到 GitHub 上，用 GitHub 管理代码，这是程序员的基本技能
- 遇到难以理解的代码，不是理解个大概就草草了事，而是要将他们拆开，理解每段代码的作用，要搞懂这串代码运行的底层原理，这比单纯的死记硬背有用的多
- 遇到难以解决的问题，要想尽一切办法去解决它，只要是问题就都有解决办法，而不是遇到问题解决不了就直接放弃
