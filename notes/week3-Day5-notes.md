# W3 Day5 学习笔记：分页处理、限速与重试
日期：2026/10/23

## 今日学习内容
- 分页：API 调用一次只返回部分数据，用 page（第几页）和 per_page（每页第几行）参数控制
- while 循环分页：循环调用 API，直到返回空列表（没有更多数据）
- time.sleep() 限速：每次调用之间等待几秒，防止因调用频繁导致 IP 被封
- 重试逻辑：请求失败自动重试最多 3 次，每次间隔 1 秒，错满 3 次才报错
- 保存 JSON: 获取完数据后用 json.dump 保存到本地文件，不用重复请求 API

## 分页原理
- 第一页：page=1, per_page=10 ——> 返回第 1~10 个仓库
- 第二页：page=2, per_page=10 ——> 返回第 11~20 个仓库
- 第三页：page=3, per_page=10 ——> 返回空列表 []，停止循环

## 为什么要限速
- 防止服务器被当成恶意爬虫，封 IP 
- 礼貌使用服务器资源
- 遵守 API 速率限制（GitHub 未认证用户每小时限制 60 次）

## 重试逻辑设计
- 最多重试 3 次
- 每次重试之间最少要等待 1 秒（给网络恢复时间）
- 状态码非 200 或网络异常都触发重试（以 4 开头的状态码(如404)重试无意义，直接输出提示信息，不重试）
- 3 次都失败才报错退出
- 区分成功和失败：status_code == 200 才算成功

## 文件路径处理
- 标准写法：`output_path = os.path.join(os.path.dirname(__file__), "文件名")`
- `__file__`：Python 内置的一个特殊变量，表示当前文件的文件路径（当前文件位置）
- `os.path.dirname`：获取当前文件所在文件夹的文件夹路径
- `os.path.join`：把多个路径片段自动拼接成一个合法的完整路径
