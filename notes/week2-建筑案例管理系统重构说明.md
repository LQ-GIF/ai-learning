# 建筑案例管理系统 v2 ——> v3 重构说明
日期：2026/10/17

## 重构目标
- 在 v2 （函数封装版）的基础上，对程序加入异常处理、日志记录、更合理的文件读写，让程序更稳定、更专业

## v2 和 v3 的对比
| 方面 | v2 版本 | v3 版本 |
|---|---|---|
| 异常处理 | 无，用户输入非法时程序崩溃 | 有，所有可能出错的地方都有try/except |
| 日志 | 无，只有 print 输出到屏幕 | 有，logging 模块同时输出到控制台和日志文件内 |
| 文件加载 | 直接 open，文件不存在时会报错 | 先检查 os.path.exists，不存在返回空列表，JSON 损坏也有处理 |
| 文件保存 | 直接写入，失败会崩溃 | 有异常处理，PermissionError 和其他异常都捕获，给用户友好提示 |
| 用户输入 | int(input())，输入字母时会崩溃 | try/except ValueError，输入字母时提示重试，不崩溃 |
| 数据文件 | cases.json | cases_v3.json（独立文件，不覆盖v2的数据） |

## 新增功能
### 1. 异常处理
- load_data()：文件不存在时返回空列表；JSON文件损坏时返回空列表；未知异常返回空列表
- save_data()：捕获 PermissionError 和其他异常，保存失败给用户提示，返回False
- 主程序菜单：输入非数字时捕获 ValueError，提示用户重试，continue 回到循环
- delete_data()：输入非数字时捕获 ValueError，提示用户重试，序号超出范围时提示

### 2. 日志记录
- 用 logging.basicConfig 配置，同时输出到 case_manager.log 文件和控制台
- 日志格式：时间 - 级别 - 内容
- 记录的操作：程序启动/退出、数据加载/保存、添加/删除案例、搜索案例、各种警告和错误

### 3. 更合理的文件读写
- 用 os.path.exists() 检查文件是否存在
- 用 with 语句安全打开文件并自动关闭
- json.dump 用 ensure_ascii=False 保留中文，indent=2 格式化
- 所有文件操作都有异常处理

## 遇到的问题
- 现象：在执行添加案例程序时，添加后的案例不会及时的自动保存到 cases_v3.json 文件中，需要关闭程序才会一次性保存添加的所有案例
- 原因：在添加案例、删除案例等能对 cases_v3.json 文件中的内容做出修改的函数中，没有调用 save_data 函数进行数据实时保存，一旦出现程序崩溃，数据有丢失风险
- 解决方法：在添加案例、删除案例等能对 cases_v3.json 文件中的内容做出修改的函数中，调用 save_data 函数

## 收获
- 理解了异常处理的重要性：让程序不崩溃，给用户友好提示
- 学会了 logging 模块的基本用法：配置日志级别、格式、同时输出到控制台和日志文件中
- 理解了日志和 print 的区别：日志可永久保存，区分异常级别、适合生产环境
- 体会到了"防御性编程"的思想：提前预料到可能出错的地方，做好处理
