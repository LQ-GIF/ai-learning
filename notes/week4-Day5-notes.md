# W4 Day5 学习笔记：README 文档编写规范
日期：2026/10/30

## 今日学习内容
- README 的作用：项目的使用说明书，别人 clone 下来看的第一份文档
- Markdown 基础语法：
    | 输出内容类型 | 语法 | 渲染效果 |
    |---|---|---|
    | 大标题 | `# 标题内容` | 整个文档的最大的字 |
    | 二级标题 | `## 标题内容` | 整个文档中第二大的字 |
    | 无序列表 | `- 内容` | 小圆点 |
    | 代码块 | `''' 代码 '''` | 灰底代码框 |
    | 粗体 | `**内容**` | 文字加粗（重点内容常用写法） |
    | 链接 | `[文字] (网址)` | 可点击文字 |
- README 结构：项目介绍/功能列表/安装/使用/示例/项目结构/已知限制/许可证

## 知识点对比表
### README 有 VS 没有
| 对比项 | 没有 README | 有 README |
|---|---|---|
| 别人理解项目 | 要根据源代码的逻辑推理使用方法 | 读 README 快速了解代码功能和使用方法 |
| 运行项目 | 不知道项目的依赖环境有哪些 | README 提供了详细的依赖环境清单 |
| 一段时间后回看项目 | 忘记项目具体功能 | 通过 README 文档立刻回忆 |

### README 必写模块
| 模块 | 写什么 |
|---|---|
| 项目介绍 | 一句话说清解决什么问题 |
| 功能列表 | 能做什么 |
| 安装方法 | 别人怎么把项目跑起来 |
| 使用示例 | 运行后长什么样 |
| 项目结构 | 目录树 |
| 已知限制 | 不适合什么场景 |
