## 今日学习内容
- 将请求代码中可复用的部分封装成一个可复用的函数
- 用 raise_for_status 去统一判断返回的状态码
- 用 HTTPError 捕获状态码异常
- 写了对于三个特定异常的 pytest 测试和 assert 断言测试

## 知识点对比
| 对比项 | 今天的写法 | 之前的写法 | 差异 |
|---|---|---|
| 状态码判断 | 用 raise_for_status 统一判断状态码 | 用 if 判断分开判断特定的状态码 | 今天的写法可以全面处理返回的所有状态码，并拦截非 2xx 3xx 的所有状态码，之前的写法只能检查 if 判断中指定的状态码 |
| 函数封装 | 把请求代码中可复用的部分封装为函数 | 昨天的项目直接写请求代码，并未封装函数 | 今天封装的函数可以沿用在之后的请求代码中，可复用性强；昨天的写法不能沿用到后续的项目中，可复用性差 |
| HTTPError 异常捕获 | 有 | 无 | 今天的写法可以捕获除 2xx 3xx 之外的所有类型的状态码，并统一输出提示信息；之前的写法只能捕获几个特定的状态码，并且提示信息要在每个 if 判断分支中单独补 |

- test_network_errors.py：对三个特定异常进行 pytest 测试

## 遇到的问题
- 问题：跑第一轮测试时，三项测试全部错误
    -原因：测试函数的最后一行要写会出问题的代码，我调用了 api_utils_2.py 文件中的 fetch_json 函数来写，但是这个函数中的代码逻辑是，只要碰到这三个特定异常中的任何一个，直接返回 None，根本不会发生我指定的异常报错，所以会出现三项测试全部错误
    - 解决方法：将最后一行代码改为调用 requests 模块直接发送 get 请求，不设置 try 进行异常捕获
- 问题：跑新增的三项断言测试时，出现三项测试全部错误的现象
    - 原因：这次我调用了 api_utils_2.py 文件中的 fetch_json 函数来写断言测试，这个函数的代码逻辑是，只要碰到这三个特定异常中的任何一个，直接返回 None，所以这个函数遇到异常输出的结果应该是 None，而我写的断言测试让输出结果等于打印出来的那条提示信息，与函数本身的输出结果不相等，所以会出现三项测试全部错误
    - 解决方法：在断言测试中，让输出结果直接等于 None
